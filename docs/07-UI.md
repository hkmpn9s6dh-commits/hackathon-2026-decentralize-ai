# 07 — UI

Gate A §4. Written before the first line of CSS.

## 1. Style preset

`documentary` — the page should feel like a **page of evidence**, not a dashboard. Warm paper
(`#f4f1e8`), warm card (`#fffdf7`), ink (`#15171b`), one hairline (`#ded8c9`). Serif for anything
that is a *claim* (headings, the model's answers); monospace for anything that is a *fact* (hashes,
ids, timestamps, key fingerprints); system sans for everything that is *chrome* (buttons, labels).

Deliberately not used: dark mode, gradients on content, glass, drop shadows beyond one soft
elevation, more than two semantic colours.

Semantic colour, and only these:

| token | value | means |
|---|---|---|
| `--ok` | `#1c5b4b` | recomputed and matched |
| `--fail` | `#a32a1e` | recomputed and did **not** match |
| `--warn` | `#8a6a1f` | reserved; not used yet |
| `--muted` | `#6a675f` | secondary text |

## 2. The ruler

Eight references. Each one is here for a specific thing to steal, not for "looks nice".

| # | Reference | What to take | What not to take |
|---|---|---|---|
| 1 | A physical shop receipt | the mental model: a strip with a header, line items, a total, and a number you can look up later | the thermal-paper aesthetic; we are not doing skeuomorphism |
| 2 | Stripe payment detail page | restraint with identifiers: monospace ids at small size, never shouting | the density; Stripe can afford 30 fields, we have 5 |
| 3 | Sigstore `rekor` / `cosign` output | the tone of a transparency log: terse, verifiable, unimpressed with itself | terminal-only presentation; readers are not all in a shell |
| 4 | crt.sh certificate transparency search | how to show a *chain* of evidence as a list with links between rows | the table-first layout |
| 5 | Signal safety numbers | comparison of two fingerprints as a first-class UI action, with an explicit "they match" verdict | the modal flow |
| 6 | RFC / IETF published text | serif headings, ink on paper, numbered sections — reads as a document that will be cited | the 90-character line length at 1280 px |
| 7 | Linear's empty state | one sentence, one verb, no illustration | the product-marketing voice |
| 8 | Our own `fintech-precise` sample (`hackathon-2026-paypal` `design/tokens.css`) | six-step type scale, the discipline of "if it does not fit, remove content, do not shrink type" | the blue; this product is not a bank |

The transferable lesson from #8, which cost a whole round of blind ranking on the PayPal entry:
**sentence-length text at 16 px minimum, and never solve overflow by shrinking the font.**

## 3. The one memory point

**The seal that cracks.**

Every receipt carries a rotated circular stamp in the top-right: `VERIFIED`, outlined, 50% opacity,
tilted −11°. It is the only decorative element on the page and it is load-bearing: it holds a
single bit of state. Change one character anywhere in that receipt and the same stamp re-renders as
`VOID` in seal-red on a red card, and the page tells you which byte moved.

Why this and not an animation: a stamp is the one piece of visual language everyone already
associates with "this document was checked by someone". We are borrowing an existing symbol and
giving it a falsifiable state.

## 4. Main screen

1280 × 800 is the reference viewport.

```
┌──────────────────────────────────────────────────────────────┐
│ ▪ Receipts   every answer, provable        [Session|Verify]  │ 60px
├──────────────────────────────────────────────────────────────┤
│ Three answers. One chain.                                    │
│ Nobody can edit them afterwards.              ← serif, 38/1.14│
│ One paragraph, max 66ch.                                     │
├──────────────────────────────────────────────────────────────┤
│ [Run the three prompts] [Tamper…] [Reset]     note →         │
├───────────────────────────────────┬──────────────────────────┤
│ ◇ RECEIPT 01        local-demo/…  │  INSPECTOR    VERIFIED   │
│ │ prompt                          │  receipt  rcpt_…        │
│ answer in serif 16.5/1.5          │  ─────────────────────   │
│ ───────────────                   │  ✓ Prompt matches …     │
│ prev … sig … kid                  │  ✓ Answer matches …     │
│                                   │  ✓ Signature            │
│ ◇ RECEIPT 02 …                    │  ✓ Link 1 → 2           │
├───────────────────────────────────┴──────────────────────────┤
│ MERKLE BATCH                    3 receipts → 1 root          │
│ published 640d…  / rebuilt 9c06… · does NOT match            │
│ [Prove answer 02 is in this batch] [Download the bundle]     │
└──────────────────────────────────────────────────────────────┘
```

**Geometry.** Page max 1240 px, gutter 28 px. Split: `minmax(0,1fr) 392px`, gap 26 px. Cards
`r=10`, padding `18 20 16 26` (the extra left padding is the chain rail). Inspector is sticky at
`top:18px` and scrolls internally at `max-height:62vh`.

**Type scale** (six steps, nothing in between): 38 / 17 / 16.5 / 14 / 13.5 / 11.5.
`h1` 38 serif, receipt answer 16.5 serif, prompt 14 muted, check label 13.5, mono detail 11.5.

**States.** Six: empty, signed, selected, tampered, verified-report, broken-report. Each has its
own text; none relies on colour alone — every check carries `✓ / ✕ / –` plus a sentence.

**Responsive.** Below 1080 px the split becomes one column and the inspector un-sticks. Below
640 px the seal is dropped rather than shrunk (it is unreadable under 56 px), the tagline goes, and
the gutter drops to 16.

**What is not on the screen.** No logo illustration, no hero image, no testimonial, no pricing, no
"trusted by". The page has exactly one job: let a sceptic check three answers.
